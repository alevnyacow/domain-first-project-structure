# Create a REST endpoint

Use this skill for an endpoint generated by `@domain-first/handlers-rest`. Read [common-workflow.md](../df-ps-scaffold/references/common-workflow.md).

1. Confirm target bounded context. Verify both config and installed dependencies include `@domain-first/handlers-rest`; the CLI exposes this operation only when configured. Inspect controller structure, route conventions, endpoint handlers, and REST registration.
2. Run `df-ps` → target context → **Presentation** → **New Handlers-REST Endpoint**.
3. Select an existing controller or **New controller** and enter its name. Select method from `get`, `post`, `patch`, `delete`, `put`. Enter only relative route segments separated with `/` (for example `:orderId/lines`). Empty input targets controller root. The full route starts with context and controller, so don't repeat them.
4. The endpoint is under `presentation/rest/<controller>/<segments>/<METHOD>.ts`. When `@domain-first/wire` is configured, the generator adds a wire under `wiring/presentation/rest/<controller>/`. Creating a controller also updates exports and shared REST registration; selecting an existing controller does not reconstruct missing registration files.
5. The endpoint's handler type is generated as `never` placeholder and must be wired to a real application handler. Implement method/path parameters using existing project conventions. Inspect all registration exports. For version 2.6.0, read [generator-2.6.0.md](../df-ps-scaffold/references/generator-2.6.0.md).

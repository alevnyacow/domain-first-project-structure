# Shared workflow for df-ps item skills

Item skills use this shared operating guide. Follow the selected item's skill for its menu path and prompts.

## Project and version

- Work in the intended project package. The CLI uses the nearest parent `package.json` as root; in a monorepo, confirm the correct package first.
- Read `domain-first.project-structure.config.json`, inspect package dependencies, target folders, representative peers, and the relevant generator version. The config controls generated integration imports even when dependencies are missing.
- Prefer the installed `@domain-first/project-structure` executable. Run `npx df-ps` when available locally. If absent and fetching is authorized, invoke `npm exec --package=@domain-first/project-structure -- df-ps` (pin a requested version). Bare `npx df-ps` might resolve an unrelated package.
- If there is no config, use `$df-ps-initialize` or perform first-run setup following that skill before scaffolding.

## Naming and collisions

Use simple lowercase kebab-case names, without suffixes the generator adds, slashes, or extensions (for example, input `place-order`, not `place-order-command`). Filenames generally preserve the supplied text while class names are derived from hyphenated words. Use nonempty hyphen-separated words. For endpoint route segments, slashes are expected.

Inspect the exact target file paths before running. The generator overwrites files with the same names and appends barrel exports without deduplicating them. Record relevant pre-existing changes, including untracked files; a dirty working tree by itself does not block work.

## Interactive session

The CLI has no documented non-interactive flags. Start it from the project root in a PTY and retain the session ID. Read each prompt before answering; menus change with config and project contents. Select: arrows + Enter. Multi-select: arrows, Space to toggle, Enter to submit. Text: value + Enter. Confirmation: explicit `y` or `n` + Enter. In JSON input, up/down are `\u001b[A` and `\u001b[B`, Enter is `\r`. Never send a guessed full sequence without inspecting intermediate prompts.

One CLI invocation handles one operation, then exits. For several items, run sequentially, inspect each result, and make only items needed by the request. A bounded context must exist before generating context-specific components; a new error namespace must exist before adding an error into it.

If terminal interaction is unavailable, give the user the command and exact choices, then state that generation has not happened. Do not claim success from submitted answers; wait for process exit and inspect files.

## Tests and integrations

The optional `testingLibrary` field makes item-specific test prompts available; it does not mean yes to every prompt. Follow the user's preference; if unclear, ask once for a multi-item task and apply consistently. Test implementation adapters and test files are separate options. Use different adapter labels to avoid filename collisions.

Select integration-dependent options only when the package is installed or the user explicitly plans to add it. Do not install dependencies or alter config without the user's request. Generated wiring calls start with empty dependency lists; when adding constructor dependencies, update wiring too.

## Review and recovery

After each operation inspect created and modified paths, imports, relative paths, barrels, wiring, and placeholder code. Complete stubs if the user asked for working behavior. Tests generated by df-ps are smoke-test templates; generating them is not the same as running them. Run tests/type checks only when requested or needed to finish the feature, and report what actually ran.

The CLI writes as prompts are answered; there is no transaction or rollback. On cancellation or failure, inspect the session and compare with the pre-run state before retrying. Do not blindly rerun (it may overwrite user edits or duplicate exports), reset the repository, or remove whole directories. Finish/repair clearly attributable partial output and preserve unrelated changes.

For generator 2.6.0 quirks, read [generator-2.6.0.md](generator-2.6.0.md). Treat those notes as version-specific observations; for other versions verify source or output first.
